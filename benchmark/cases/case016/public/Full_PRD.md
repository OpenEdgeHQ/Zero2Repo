# prosecheck — Full Product Requirements Document

## Product overview

**prosecheck** is a local detector for AI-writing patterns. It is a command-line tool and an agent plugin. There is no website and no hosted version. Nothing the user writes is uploaded; there is no account; no text leaves the machine. Any site offering a service under this name is unrelated to this project.

A first-time user installs the prosecheck plugin into a coding agent (Claude Code, or another agent via the portable contract), restarts, and runs `/prosecheck doctor`. When the install is sound and the tool is on, the doctor answers with four successful-check lines. From then on, two layers work together. A writing contract is placed in the session (and into any subagent) so prose deliverables are shaped as they are written. After a supported file-edit tool saves a prose file, a saved-file guard scores the first 262,144 characters of extracted prose against a catalogue of 71 documented patterns and, when the score is above the active threshold, names the flagged spans and asks for them to be fixed. The same detector can be run by hand on a file path or on standard input. Python standard library only, no network, no model. Prose only, never code.

This document specifies **user- and integrator-observable behavior only**. Exact published symbol names, import paths, and call spellings belong in the Interface Contract, not here. Every feature point below corresponds to behavior that exists in the finished prosecheck product (version 0.9.3). Feature points are ordered so foundational capabilities come first; a later feature point may refine an earlier one only when it says so explicitly.

## Terminology

| Term | Meaning in this PRD |
| --- | --- |
| **prosecheck** | The product: a local prose-pattern detector and the agent plugin that wraps it. |
| **Detector** | The command-line scanner. Given a file or standard input, it either prints a structured report (score, band, pattern findings) or, with the cleanup switch, prints scrubbed text. |
| **Catalogue** | The 71 documented AI-writing patterns, numbered 1–71, with Before/After examples in the pattern catalogue. A pattern describes prose, never a writer. |
| **Machine-checked pattern** | One of the 62 catalogue numbers that the detector can report on a scan. The other 9 numbers have no detector and are worked only by reading during a rewrite. |
| **Score-moving pattern** | One of the 50 machine-checked catalogue numbers that can change the 0–100 score. The remaining 12 machine-checked numbers are **writing advice**: when they appear in the report they count for nothing. |
| **Score** | An integer from 0 through 100 inclusive. It is a triage heuristic on the writing in front of the detector, not a calibrated authorship classifier. |
| **Band** | One of five named ranges of the score: `clean`, `light tells`, `mixed`, `heavy tells`, `pervasive tells`. Every band describes the prose; none of them names an author. |
| **Hook phrase** | The plain-language rendering of a band used by the plugin: `reads clean`, `reads mostly clean`, `reads with some AI tells`, `reads with heavy AI tells`, `reads with pervasive AI tells`. |
| **Confidence** | How much the score is worth, reported as `none`, `low`, `moderate`, or `high` from word count and how many distinct score-moving families fired. |
| **Writing contract** | The always-on prose rules injected into a session, a prompt, and a subagent. It governs prose deliverables only. It never touches source code, comments, commits, configuration, or the chat register. |
| **Saved-file guard** | The plugin layer that, after a supported file-edit tool writes a prose file, scores that file and, when flagged, returns a nudge naming the file, the hook phrase, the score, the band, and the fired pattern labels. |
| **Level / mode** | The one-word operating level stored for the install: `lite`, `full`, `strict`, or `off`. Default is `full`. |
| **Prose file** | A saved file whose extension is in the twenty-format set (FP-02). |
| **Extracted prose** | The visible text the detector actually scores: the file body for plain text; the document text pulled out of a supported archive or notebook. |
| **Scan window** | The first 262,144 characters of extracted prose. Everything past that window is unread. Character-layer rules use the same window. |
| **Character cleanup** | The detector’s cleanup switch: strip invisible and zero-width codepoints that carry no meaning where they sit, normalize non-standard spaces to ordinary space (U+0020) where they are not load-bearing, fold mixed-script lookalikes inside Latin runs to ASCII, and trim stray whitespace. Visible text is left alone. |
| **Session ledger** | A per-session record of what the guard scored or skipped. It holds each file’s base name, score, band, and up to five pattern labels — never the document text and never the full path. |
| **Host agent** | The coding agent that loads the plugin (Claude Code and, via `/prosecheck init`, other agents that read `AGENTS.md` or a Cursor rule). |
| **Core capability** | A user-observable capability that reflects prosecheck’s design goal; acceptance must prove the real detector or plugin behavior, not a stub. |
| **Discrimination** | An assertion’s ability to distinguish a faithful implementation from a hollow, skipped, or proxy one. |

## Public surface inventory

prosecheck is a **command-line detector** with a companion **agent plugin**. The detector needs Python 3.9 or newer and nothing else. The plugin’s saved-file and command hooks need Node.js. There is no installable package, no compiled extension, and no runtime third-party dependency.

The public, independently verifiable surfaces, grouped the way later feature points verify them, are:

- The detector command: a file path or standard input in, a structured report or scrubbed text out; optional cleanup and resampled-interval switches; help (FP-01, FP-03).
- Extraction of visible prose from the twenty supported formats, with the 512 KB / 4 MB acceptance caps and the 262,144-character scan window (FP-02).
- The writing contract, placed at session start, on the prompt, and inside a subagent, including the one-time first-run welcome (FP-04).
- The saved-file guard on Write, Edit, MultiEdit, NotebookEdit, and apply_patch, including Codex apply_patch payloads (FP-05).
- The `/prosecheck` command (and the namespaced form `/prosecheck:prosecheck`): levels, status, show, check, doctor, stats, init, help (FP-06).

Feature points below group these entries by independently verifiable capability. They do not invent additional product surfaces.

The bundled skill file instructs a host agent how to rewrite flagged prose (style profiles, silence, preservation rules). That rewrite is performed by the host agent, not by the detector. It is not a feature point below. The detector, the contract, and the guard are the graded product.

## Non-functional constraints

- **Form factor:** A Python standard-library detector plus Node.js plugin hooks. No compiled extensions, native code, GPU, or accelerator are required or claimed. No runtime third-party libraries.
- **Language floor:** Python 3.9 or newer for the detector. Node.js for the hooks.
- **Platforms:** Linux, macOS, and Windows. This case’s acceptance targets Linux with a supported interpreter. Path, encoding, and line-ending behavior that the product already handles (UTF-16, UTF-8 byte-order mark, carriage-return/line-feed) remains an obligation on every platform.
- **Hardware:** CPU-only. The mandatory execution substrate is a real host able to invoke the detector from this repository’s source tree and, for plugin features, to run the hooks with Node.js. There is no removable accelerator profile. Do not write a negative-control clause that disables the package, the interpreter, or the standard library.
- **Network:** The runtime contains no network client and no telemetry. Analysis is local. The public benchmark harness, when used, reads a user-supplied local dataset and opens no socket. This is a hard product constraint, not a fallback.
- **Privacy:** The plugin stores a one-word mode flag and a per-session ledger. A ledger whose last modification is more than seven days old is gone by the time a later session is in use. Ledger files are written with owner-only permissions.
- **Scope of language:** English prose is the supported scope. The score describes patterns in that prose. It does not establish authorship, truth, or overall writing quality, and it must not be used to accuse a person.
- **Determinism:** The same extracted prose, on the same detector, produces the same report. There is no model and no random component in the default scan. The optional resampled interval (FP-01) is the sole opt-in extra; its presence or absence does not change the point score.

## Capability discrimination (global)

Every feature point below is a **core capability**. None is an accelerator-backed mandatory-substrate GPU feature. The mandatory `cpu_baseline` profile only means the detector and hooks run on CPU; it does not license a negative control.

For every feature point:

- **Present:** Real prosecheck behavior matches the described outcomes when the detector is invoked on named inputs, or when the plugin hooks are fired with the payloads a host agent sends.
- **Absent / hollow:** A stub that always returns a fixed score; a scanner that flags every adjective; a cleanup that deletes all non-ASCII; a guard that scores source code; a doctor that prints success without running the detector; an init that writes a machine-specific path into a portable contract.

Cheaper proxies (a hosted API, a third-party model, a canned score table, or treating every file as plain UTF-8 without extraction) do **not** satisfy core capabilities. There is no approved degradation scenario that replaces the local detector for a core capability.

## Non-goals

- Proving whether a model wrote a document. The score ranks writing; it is not a yes/no authorship classifier. The public matched benchmark’s ROC-AUC figures are ranking results, not per-document accuracy, and they are not a graded obligation of the detector command.
- Reading PDF or RTF. Those extensions are logged as binary by the guard and yield no extracted text from the detector.
- Scoring a file written only by a shell command. That path reaches disk without passing Write or Edit; the guard does not see it. The writing contract still applies to whoever composed the text.
- A website, account, or hosted service.
- Consulting or optimizing against third-party authorship, plagiarism, or integrity detectors.
- Rewriting a `.docx`, `.epub`, `.odt`, or `.ipynb` in place when cleanup is requested. Cleanup prints extracted plain text; writing that back over the original would replace the document with loose text.
- Treating the bundled skill’s rewrite, silence, and style-profile instructions as a graded detector obligation. Those are instructions for a host agent.
- Treating the recorded-session demo, the documentation checker, the public benchmark harness, or the status-line helper as product surfaces a first-time user must have.

## Feature points

### FP-01: Local detector scan, 0–100 score, and five bands

**Public entry:** The prosecheck detector command. The caller supplies a single file path, or supplies no path and pipes text on standard input. Optional switches: cleanup (FP-03), a resampled interval on the score, a request for the usage message, and a double-dash that stops option parsing so a file name may begin with a dash. This feature point is the report. Extraction of archives and notebooks is FP-02; the cleanup switch’s text output is FP-03.

**Normal behavior:**

- On readable non-empty extracted prose, the detector prints a structured report and exits successfully. The report has two kinds of content: **findings** and **metrics**.
- Each finding is one fired machine-checked pattern. It carries a human-readable label, a hit count, and up to three short samples drawn from the text. Catalogue numbers that did not fire are omitted. The nine catalogue numbers with no detector (7, 9, 28, 29, 43, 45, 49, 52, 53) never appear as findings.
- Metrics always include: how many characters were scanned (capped at 262,144); a two-valued indication of whether the extracted prose was longer than that window (the “not longer” value when extracted prose is at most 262,144 characters; the “longer” value when it exceeds that window), distinguishable from the scanned count, the score, the band, and the confidence; the integer **score** from 0 through 100; the **band** name; a **confidence** label (`none`, `low`, `moderate`, or `high`) and, when confidence is not `high`, a reason that a caller can read; a count of fired findings; and character-layer counts for invisible/zero-width characters, non-standard spaces, and mixed-script lookalikes.
- The five bands, as ranges of the score, are: `clean` (0–20), `light tells` (21–40), `mixed` (41–60), `heavy tells` (61–80), `pervasive tells` (81–100).
- The catalogue holds 71 patterns, numbered 1 through 71, in seven groups. The detector’s machine-checked set is the 62 numbers that are not in the no-detector list above. Of those 62, **50 can move the score** and **12 are writing advice** (reported, weight zero). The twelve that belong to that weight-zero set are: 4 (hyphenated cliché pairs), 19 (filler phrases), 22 (persuasive authority tropes), 41 (mechanical sentence-length alternation), 42 (opener repetition), 46 (semicolon and parenthesis underuse), 54 (hedge stacking), 55 (contraction absence), 58 (em-dash overuse), 60 (curly quotation marks), 61 (hyphen-for-en-dash in numeric ranges), and 68 (trailing / stray whitespace). That list is inventory of the set, not a per-number graded leftover. The graded score-neutrality duty is only the named constructable probes: opener repetition, hedge stacking, trailing whitespace, and the parallelism form of catalogue 17. When a writing-advice finding appears on one of those probes, the 0–100 score equals the score of the same prose with that phrasing removed, once score-moving findings are held equal. The other listed advice numbers are members of that same set; they are not independently graded observations and they are not inputs a later check must invent. Negative parallelism (catalogue 17) is reported as advice in its parallelism form on the named probe; a distinct tailing-negation form under the same number still appears as a finding and can move the score. The two forms of 17 are told apart by which named input produced the finding and by whether the score moved, not by a required label wording.
- The 71 catalogue titles are: (1) AI vocabulary; (2) model-dialect vocabulary; (3) promotional language; (4) hyphenated word-pair overuse; (5) “simple yet X” cliché; (6) stacked adjective chains; (7) rule of three overuse; (8) synonym cycling; (9) generic character naming in fiction; (10) significance inflation; (11) notability name-dropping; (12) vague attributions; (13) article-titles-as-proper-nouns; (14) conservation / ecosystem padding; (15) false ranges; (16) superficial -ing tail clauses; (17) negative parallelisms and tailing negations; (18) “Not X, just Y” / “No X, just Y”; (19) filler phrases; (20) empty pivot phrases; (21) outcome speculation tails; (22) persuasive authority tropes; (23) editorial interjections; (24) self-thoroughness phrases; (25) question-answer rhetorical pattern; (26) “concrete evidence” defense phrase; (27) compulsive intro hooks; (28) meandering intro; (29) prompt echo; (30) diff-anchored writing; (31) signposting and announcements; (32) cataloguing lead-ins; (33) inline-header vertical lists; (34) mid-essay bullet injection; (35) fragmented headers; (36) formulaic challenges sections; (37) transition cluster overuse; (38) compulsive conclusion phrases; (39) generic positive conclusions; (40) sentence-length monotony; (41) mechanical sentence-length alternation; (42) opener repetition; (43) avoidance of fragments and run-ons; (44) uniform paragraph length; (45) identical paragraph structure; (46) semicolon and parenthesis underuse; (47) chatbot artifacts; (48) sycophantic / servile tone; (49) RLHF / helpful-assistant register; (50) knowledge-cutoff disclaimers; (51) copula avoidance; (52) passive voice and subjectless fragments; (53) two-way passive-voice drift; (54) excessive hedging; (55) contraction absence; (56) boldface overuse; (57) emojis; (58) em-dash overuse; (59) title case in headings; (60) curly quotation marks; (61) hyphen-for-en-dash in ranges; (62) invisible / zero-width characters; (63) placeholder / Mad-Libs text; (64) chatbot reference-markup leak; (65) AI tracking params; (66) homoglyph / mixed-script confusables; (67) non-standard spaces; (68) trailing / stray whitespace; (69) canonical marketing-slop phrases; (70) decorative horizontal rules; (71) degenerate repetition. When a machine-checked pattern fires, the finding’s label identifies that numbered kind to a caller; two reports are told apart by which numbered kind the label points at, not by whether the label copies a listed title string. The nine numbers with no detector still never appear as findings, so they have no label to check. Catalogue 17 may be labeled as either of its two forms or as the combined title.
- Scoring counts **distinct catalogue families**. Isolated AI-vocabulary in otherwise ordinary short prose — a one-word “delve” probe, or “delve” plus “tapestry” as two hits of that same family — stays in `clean` / `light tells` (at most 40). A two-hit one-family score that lands anywhere in 0–40 honours that band; treating those two hits as three or more distinct score-moving families, and taking that floor of 45, is the wrong outcome. Adding the named chatbot-artifact probe (“I hope this helps”) on that same short isolated base takes the two-distinct-family floor of at least 25. Adding the named opener-repetition probe (“The system…” three times) on that same base stays in that band and, once score-moving findings are held equal, does not raise the score relative to the isolated arm. Leaving `clean` / `light tells` is the named multi-family dense-slop / AI-register contrast, not a hit-count of AI-vocabulary alone and not a one-family integer cap below 25.
- A **decisive** finding is one of: invisible/zero-width characters (62), placeholder text (63), chatbot reference-markup leak (64), AI tracking params (65), mixed-script homoglyphs (66), article-title-as-proper-noun (13), chatbot artifacts (47), knowledge-cutoff disclaimer (50), sycophantic tone (48). Two distinct decisive families in one scan raise the score to **at least 65**. A single decisive family raises it to **at least 45** only when confidence is above `low`. A single decisive family at `none` or `low` confidence does not take that 45 floor.
- On a document shorter than 120 words, two distinct score-moving families from the lexical/rhetorical/chatbot set raise a floor of 25, and three or more raise a floor of 45. On a document of 400 words or more, five distinct score-moving families raise a floor of 25, and six or more raise a floor of 45.
- Rhythm-only evidence (sentence-length monotony, mechanical alternation, uniform paragraph length, contraction absence) cannot by itself push a document above 40. A document of three even-length factual sentences — “Snow covered the high passes. Trucks waited below the ridge. Crews cleared the road slowly.” — whose only extra score-moving evidence is among those four kinds, scores at most 40. Unlabeled even-length, equal-paragraph, short-then-long, or contraction-absence pads are not each required to fire those kinds. A short factual human paragraph stays at or below 40. A short dense-slop paragraph of similar length scores at least 20 points higher than that factual paragraph.
- Confidence is `none` below 40 words; `low` below 120 words, or below 300 words with only one score-moving family; `moderate` below 300 words otherwise; `high` at 300 words or more. The saved-file guard (FP-05) treats `none` as “do not nudge,” even if the point score is above the threshold.
- Inside the scan window, fenced and indented code, consecutive quoted (blockquote) runs, markdown tables, badge lines, and YAML front matter do not generate findings. A nested fence that uses a longer opening run than an inner fence still keeps the inner example out of findings. An indented continuation of an ordinary paragraph still generates findings as prose, not as a code block.
- A banned word that is split only by in-word zero-width characters still fires the same finding as the unsplit word. A mixed-script lookalike inside a Latin word both fires mixed-script homoglyphs (66) and still matches the same vocabulary finding as the ASCII spelling.
- Constructable fires (a finding appears): a passage that stacks “delve”, “tapestry”, “pivotal”, “showcase”, “seamless” fires AI vocabulary (1); “genuinely fascinating” together with “game-changer” / “supercharge” fires model-dialect (2) at two or more combined hits, and a single dialect word does not; “nestled in the heart of” / “world-class” fires promotional language (3); “simple yet powerful” fires 5; four adjectives before one noun (“bold, ambitious, transformative, innovative initiative”) fires 6, while a list of concrete nouns (“apples, oranges, bananas, grapes and pears”) does not; three or more synonym-cluster members for the same referent (protagonist / main character / central figure / hero, or companies / firms / organizations / businesses) fire 8, and a cluster member buried inside a longer word (“nanotechnology”) does not; “studies suggest” / “experts argue” fires 12; “The List of … is a comprehensive resource” fires 13; “plays a vital role in its ecosystem” fires 14; “from the humble … to the mighty” fires 15, while “from 9 to 5”, “from 0 to 100 degrees”, “from Boston to Chicago”, and “from biology to chemistry” do not; a comma plus “highlighting” or “underscoring” fires superficial -ing tail clauses (16); a comma plus “paving the way for” fires outcome-speculation tails (21); a comma plus “no wasted motion” fires the tailing-negation form of 17 and can move the score; “It’s not just about the resin holding the fibres in place; it’s about how the laminate fails under load” fires the parallelism form of 17 and does not fire 18, and that finding does not change the score relative to the same prose with the parallelism removed; “it’s not just X, it’s Y” and “No fluff, just results” fire 18 and are not the parallelism-form 17 fire, while “She is not a teacher, but a researcher” and “I did not sleep well because of the noise” do not; “it’s worth noting that” fires 20; “I hope this helps”, “as an AI language model”, and “here is a draft” fire 47; “Great question!” with chatbot punctuation fires 48 (sycophantic) and does not also fire 47, while ordinary prose containing “a great question in …” fires neither; “as of my last training” fires 50; “serves as” / “stands as a testament” fire 51 / 10; two or more hedges in one sentence fire 54, and the month name “May” is not a hedge; “[Your Name]” / “[INSERT EMAIL]” fire 63; “oai_citation” / “citeturn0search2” fire 64; a URL whose query string contains a chat-UI `utm_source` (including one with a sentence-ending period) fires 65, while `utm_source=chatgpt.com.au` (a different domain) does not; a Cyrillic letter inside an otherwise Latin word fires 66, while a genuine Cyrillic sentence, a native mixed-script proper name, and a single-script non-Latin URL do not; a TAG-block or zero-width character in English prose fires 62; a no-break space between two English words fires 67 and not 62; trailing spaces at end of line or end of file fire 68, while a single conventional trailing newline does not; two or more of Additionally / Furthermore / Moreover / However in one paragraph fire 37, and a single “However you slice it” does not.
- A dense AI-register sample that includes chatbot openers, stacked vocabulary, “not just X, it’s Y”, a knowledge-cutoff hedge, and a generic upbeat close fires at least ten findings including AI vocabulary, copula avoidance, chatbot artifacts, sycophantic tone, and a generic positive conclusion, and its score is strictly higher than a matched humanized sample of similar length. That humanized sample fires **no** findings. That AI-register sample and the dense-slop paragraph do not emit the parallelism form of 17.
- A leading UTF-8 byte-order mark and carriage-return/line-feed line endings on otherwise human prose do not add invisible-character findings and do not raise the score into `mixed` or above. An interior zero-width character in the same prose does add an invisible-character finding.
- When the resampled-interval switch is on and the document has at least four sentences, metrics include a low/high interval on the score. With fewer than four sentences, the interval is omitted and the metrics state that there are too few sentences. The interval does not replace the point score. The resampling count and seed are the implementer’s and are not scored.

**Boundary / error behavior:**

- Empty extracted prose (including a file that decodes to nothing, a notebook with no markdown cells, an empty archive, PDF, and RTF) does not print a report. The process fails with a structured error on the error stream, a failing status, and no traceback. Those named empty sources share one identifying kind with each other and with empty standard input. That kind is distinguishable from the identifying kind of an unreadable path or of a supported-archive extension whose bytes are not a readable zip, and from the unknown-option kind. The empty-input kind is not a required field name or a required phrase.
- An unreadable path, or a file whose extension is a supported archive type but whose bytes are not a readable zip, shares that failure shape — structured error on the error stream, the same failing-status family as empty input (not the unknown-option status), and no traceback — but a different identifying kind from empty input. Status-alone versus unknown option does not identify empty input, because unreadable shares that status family.
- An unknown option fails with a distinct failing status and a structured error that identifies the unknown option and points at help.
- Help (the help switch or the short help alias) prints the usage message to standard output and succeeds. Usage names the cleanup switch, the interval switch, the double-dash, and the single-file operand.
- Two or more file operands still succeed: the first file is scanned, and the error stream states that only one file at a time is supported and names the file that was scanned. A silent drop of the extra files is not this product.
- A file whose extracted prose is longer than 262,144 characters is still scored. Metrics carry the “longer” value of the two-valued longer-than-window indication and report 262,144 characters scanned. A file of exactly 262,144 characters is still scored and carries the “not longer” value, with the same scanned count. Findings, including character-layer findings, are computed only on that prefix. A homoglyph or invisible character that sits only past the window does not appear as a finding.
- A binary-looking buffer that is not UTF-16 and contains a NUL byte is treated as not text: it yields empty input (failure), not a report full of invented invisible-character hits. UTF-16 with a byte-order mark is decoded as text.
- Standard input and standard output use UTF-8. Cleanup (FP-03) preserves the input’s newline convention on output so a file that arrived with carriage-return/line-feed still has it.

piping the longer humanized sample that discusses coding assistants with contractions and fragments yields **zero** findings; piping the longer AI-register sample that opens with “Certainly!” / “Great question” and closes with “the outlook is bright” yields at least ten findings including AI vocabulary (1), chatbot artifacts (47), sycophantic tone (48), and a generic positive conclusion (39), and a strictly higher score than the humanized sample, and does not emit the parallelism form of 17; piping “It’s not just about the resin holding the fibres in place; it’s about how the laminate fails under load” yields a parallelism-form 17 finding that does not fire 18 and does not change the score when that phrasing is removed; piping the three-sentence snow-and-road rhythm-only document yields a rhythm-class finding among sentence-length monotony, mechanical alternation, uniform paragraph length, and contraction absence, and a score of at most 40; a document whose only extra finding is a named writing-advice probe (opener repetition on “The system…” three times, two hedges in one sentence, or trailing spaces) does not receive a higher score than the same document with that pattern removed, once score-moving findings are held equal; a scan that fires both placeholder text and a chat-UI tracking parameter (two decisive families) has score at least 65; a long human document with a single “Great question!” prepended, or a single tracking-parameter URL appended, does not reach the guard’s default flag condition in FP-05 (score above 40 **and** confidence not `none`); metrics on a file of exactly 262,144 characters carry the “not longer” value of the two-valued longer-than-window indication and 262,144 scanned; metrics on a file of 262,145 or more characters carry the “longer” value and 262,144 scanned, and the scan is still a structured success; “delve” inside a markdown fence does not fire AI vocabulary, and the same word after the fence does; empty standard input fails with a structured error on the error stream, a failing status, and no traceback, and that identifying kind is the same kind every other empty-extracted-prose source uses and differs from an unreadable path and from a supported-archive extension whose bytes are not a readable zip as well as from unknown option; two file paths warn on the error stream and scan only the first; unknown option fails with a distinct failing status and a different identifying kind from empty input.
- Failure / absence: every document scores 50; findings are printed for catalogue 7, 9, 28, 29, 43, 45, 49, 52, or 53; a named writing-advice probe (opener repetition, hedge stacking, trailing whitespace, or the parallelism form of 17) changes the score; “Great question in the colonies” fires chatbot or sycophantic findings; a humanized sample is flagged; a fenced slop sample is flagged; an at-cap file and an over-window file carry the same longer-than-window indication, or that indication is absent; extra file operands are dropped with no message; empty input prints a zero score instead of failing.

### FP-02: Twenty-format extraction, size caps, and the 262,144-character window

**Public entry:** The same detector command as FP-01, when the operand is a file whose extension is one of the twenty supported formats, and the saved-file guard (FP-05) / `/prosecheck check` (FP-06) when they accept a path. This feature point is **getting prose out of the file** and **refusing or truncating** when the file is too large or not readable as prose. Scoring of the extracted text is FP-01.

**Normal behavior:**

- The twenty supported formats are exactly: `.md`, `.mdx`, `.markdown`, `.txt`, `.text`, `.rst`, `.tex`, `.org`, `.adoc` (plain text); `.docx`, `.docm`, `.pptx`, `.pptm`, `.xlsx`, `.xlsm`, `.odt`, `.odp`, `.ods`, `.epub` (zip-based documents); and `.ipynb` (notebook). Plain text is accepted up to **512 KB**. Zip-based documents and notebooks are accepted up to **4 MB**. Those caps are file size on disk, as the guard and `/prosecheck check` enforce them, in binary units: a kilobyte is 1,024 bytes, so the plain-text cap is 524,288 bytes and the zip/notebook cap is 4,194,304 bytes (4 MB, which is 4096 KB). A file whose size equals its cap is accepted; one byte more is over the cap. The detector command itself reads a path it is given; the plugin refuses oversize files before scoring (FP-05, FP-06).
- For the nine plain-text extensions, the extracted prose is the decoded file body (UTF-8 with optional leading byte-order mark, or UTF-16 with a byte-order mark). A leading mark is not part of the prose and is not an invisible-character finding.
- For `.docx` / `.docm`, visible paragraph text of the main document is extracted, without XML markup.
- For `.pptx` / `.pptm`, visible text of slides is extracted in slide order, without markup.
- For `.xlsx` / `.xlsm`, cell text is extracted in sheet order. Shared-string cells, inline-string cells, and string-typed cells are all read. Shared-string indices are followed, so an unused first shared string is not emitted merely because it is first in the table. Adjacent cells stay separated (a line or cell boundary between them). Formula caches that expose a string value are included; a numeric cell such as 42 is not required to become prose. Out-of-range or non-numeric shared-string indices are skipped, not treated as text.
- For `.odt`, `.odp`, and `.ods`, visible text of the content document is extracted. Linked text, spans, explicit space runs, tabs, and line breaks are preserved as ordinary spaces, tab characters, and newlines. Markup is not leaked.
- For `.epub`, chapter HTML/XHTML is read in reading order (so chapter 10 follows chapter 2, not the other way around). Navigation, style, and script content are excluded. Inline emphasis and links contribute their visible text, not their tags. An undeclared namespace prefix on an attribute does not drop the chapter.
- For `.ipynb`, only markdown cells are extracted, joined as prose. Code cells, outputs, and comments inside code are not prose and must not appear in the extraction. A notebook whose markdown cells hold dense slop therefore scores like that slop; a notebook whose only “delve / tapestry” string lives in a code cell does not pick it up.
- The same English slop paragraph, saved as `.md` and as `.docx` (and as `.pptx`, `.xlsx`, `.odt`, `.epub`), produces extracted prose that still contains the distinctive words of that paragraph (for example “delve” and “game-changer”) and, once scored (FP-01), a score of at least 40. The same human paragraph about a stone bridge, saved as `.docx`, scores below 40.
- XML markup characters from the archive must not appear in the extracted prose.
- The extracted prose of a zip-based document or a notebook does not begin or end with whitespace. Line breaks separate consecutive paragraphs, slides, cells, chapters, or markdown cells; nothing is added before the first text or after the last, and whitespace at either end of the extracted text is dropped. A single paragraph therefore extracts as exactly its visible text. The 262,144-character window, and whether the extracted prose is longer than it, are measured on that text.

**Boundary / error behavior:**

- `.pdf` and `.rtf` are not among the twenty formats. The detector treats them as having no extracted prose (empty input, FP-01). The guard does not score them; it records them on the session ledger as binary (FP-05).
- A file named like a supported archive whose bytes are not a zip fails the detector with a structured error and no traceback (FP-01). An archive that is a zip but has no extractable prose yields empty input.
- A notebook that is not valid JSON, or whose cells are not a list of objects with string (or list-of-string) markdown sources, yields empty extracted prose. The detector command then fails as empty input. It does not print a traceback.
- The archive-member size cutoff is the implementer’s and is not scored.
- The 262,144-character window is measured on the extracted prose, not on the compressed archive. Character-layer rules (62, 66, 67, 68) use that same window: an invisible character placed only after character 262,144 is not a finding.
- Source-code extensions (for example `.py`, `.js`) are not among the twenty formats. The guard leaves them alone (FP-05). If the detector command is aimed at such a file anyway, it is read as plain text; that is not a plugin obligation.

**Verifiable oracle:**

- Success: a zip-based `.docx` / `.pptx` / `.xlsx` / `.odt` / `.odp` / `.ods` / `.epub` whose body contains “delve” and “game-changer” in English slop yields extracted text containing those words and no `<` markup, and a score of at least 40; a `.docx` whose body is the stone-bridge human paragraph scores below 40; a spreadsheet with both shared strings and inline strings yields both; a spreadsheet that maps cells to shared-string indices 2 then 1 emits those strings in cell order, not table order, with a boundary between cells; an OpenDocument paragraph “Keep linked words here.” plus an explicit two-space run, a tab, and a line break extracts as that sentence, then “two  words”, a tab, “tab”, a newline, “line.”; an EPUB with a `<nav>` toc, a `<style>` block, and a `<script>` alongside a real paragraph yields the paragraph and not the nav/style/script strings; an EPUB chapter that uses an undeclared prefix still yields its paragraph; a notebook with slop in a markdown cell and “delve” in a code cell extracts the slop and not the code, and scores at least 40; a notebook with only a code cell extracts empty and the detector command fails as empty input; a truncated or renamed non-zip `.docx` fails cleanly with a structured error and no traceback; a `.pdf` is not extracted as prose.
- Failure / absence: only `.txt` is read; a `.docx` is refused; markup leaks into the text; spreadsheet cells are concatenated with no boundary; EPUB nav leaks; code cells are scored; a broken notebook crashes with a traceback; PDF bytes are parsed as prose.

### FP-03: Deterministic character cleanup

**Public entry:** The detector command with the cleanup switch, on a file path or on standard input. Without the switch, the same character layer is **reported** as findings 62, 66, 67, and 68 and as metrics counts (FP-01); it is not applied to the text. This feature point is the switch that **emits scrubbed text instead of the report**.

**Normal behavior:**

- Cleanup prints the scrubbed text to standard output and exits successfully. It does not print the structured report.
- What is removed: invisible and zero-width characters that have no job where they sit (zero-width space between Latin letters, word joiner, a mid-text byte-order mark, a left-to-right mark in a left-to-right English run, TAG-block payloads, a variation selector with no glyph base). After cleanup, a rescan (FP-01) reports zero invisible-character hits and zero non-standard-space hits for those inputs.
- What is normalized: non-standard spaces that are not doing real work (no-break space between two English words, ideographic space in English) become ordinary space (U+0020). Spaces that are load-bearing stay (a no-break space before French punctuation; a narrow no-break space inside a figure such as “40 EUR”).
- What is folded: mixed-script homoglyph letters inside a Latin word fold to ASCII (“pаssword” / “pаyment” / “sсript” with Cyrillic vowels become “password” / “payment” / “script”). Genuine single-script non-Latin words, sentences, and URL runs are not folded.
- What is trimmed: trailing spaces and tabs at end of line and at end of file. A file that ended in a newline still ends in a newline. Leading blank lines are dropped; the first line’s own indentation is kept (four leading spaces remain, because they open a markdown code block). Horizontal tabs, line feeds, and carriage returns inside the body are never stripped as “invisible.”
- Cleanup agrees with detection: a character the scrub keeps is not counted as an invisible character or a stray space on a scan of the original. An England-flag tag sequence, a Japanese ideographic variation sequence, a family emoji joined with zero-width joiners, an emoji with variation selector 16, a keycap sequence, a Persian non-joiner inside a word, a Devanagari joiner, Arabic with bidirectional marks, Thai zero-width word breaks, a genuine Cyrillic or Greek sentence, combining accents, café, Japanese prose, and mathematical Greek stay byte-for-byte.
- A TAG-block payload after a flag terminator is still removed; the flag itself stays. An eight-thousand-character TAG run, or a thirty-two-thousand-space run, still finishes under the detector command (with or without cleanup) within **8 seconds** — the same budget the saved-file guard gives piped text (FP-05). Those inputs do not hang the command.
- For `.docx`, `.epub`, `.odt`, or `.ipynb`, cleanup prints the extracted plain text, not a rebuilt document, and does not write the original path. After the process exits, that path’s bytes equal the bytes from before the run.

**Boundary / error behavior:**

- Empty input, unreadable files, unknown options, and extra file operands follow FP-01. Cleanup does not turn empty input into success.
- Cleanup never invents words, never deletes a Latin letter that was actually there, and never converts a genuine Cyrillic word into Latin lookalikes.
- Trailing whitespace at end of line is removed even when two spaces were meant as a markdown hard break. That collapse is required, not optional.

**Verifiable oracle:**

- Success: “Cellulose” plus a zero-width space plus “ is” plus a no-break space plus “dense.” plus a TAG character plus trailing spaces, cleaned, is “Cellulose is dense.” (with the input’s trailing newline if it had one) and a rescan reports no 62 / 67 / 68 findings; “The pаssword field is wrоng.” (Cyrillic vowels) cleans to “The password field is wrong.”; “Москва is the capital of Russia.” is unchanged; the England flag sequence is unchanged and a following TAG payload is removed; “    indented code block” keeps its four spaces; a file that ended with a newline still does; café and 日本語 are unchanged; a `.docx` path with the cleanup switch prints extracted text, not zip bytes; an eight-thousand-character TAG run and a thirty-two-thousand-space run each finish within 8 seconds with or without the cleanup switch.
- Failure / absence: cleanup still prints a score report; zero-width characters survive; genuine Cyrillic is folded to Latin; emoji joiners are stripped; four-space indentation is trimmed; a document file is rewritten as a zip; an eight-thousand-character TAG run hangs past 8 seconds.

### FP-04: Always-on writing contract at session start, on the prompt, and in a subagent

**Public entry:** The plugin’s session-start, prompt-submit, and subagent-start hooks, as a host agent fires them: JSON on standard input, text or a JSON envelope on standard output. `/prosecheck init` (FP-06) writes the same contract into the project for agents that are not Claude Code. This feature point is **placing the contract in context**. Scoring a saved file is FP-05. Changing the level is FP-06.

**Normal behavior:**

- When the level is `lite`, `full`, or `strict` (the default when no flag has been stored is `full`), session start emits the writing contract for that level. When the level is `off`, session start emits nothing.
- The contract’s scope is prose deliverables only (documents, README/markdown prose, CVs, cover letters, emails, reports, essays, articles, drafted text the user will publish or send). The graded wrong-scope observation is that the delivery does **not** say the contract applies to source code. The never-touch list (code comments, commit messages, JSON/YAML/config, CLI output, logs, error messages, the conversational register of chat) is inventory of that same scope, not independently graded leftovers and not a required slogan token. Compose-with-other-modes (a chat-compression mode owns chat; a code-simplicity mode owns code; this contract owns deliverable prose) is narrative colour, not a graded slogan.
- The contract’s prose rules, so a host agent can follow them, include: vary sentence length irregularly (no metronome, no mechanical short-long alternation); a banned-vocabulary list that includes delve, tapestry, pivotal, crucial, leverage, robust, seamless, foster, underscore, showcase, landscape (abstract), journey (abstract), realm, multifaceted, holistic, testament, vibrant, comprehensive, plethora, myriad, boast, elevate, empower, unlock, game-changer, supercharge, genuinely, fascinating, nuanced; banned moves including rule-of-three flourishes, “it’s not just X, it’s Y”, hedge stacking, signposting (“let’s dive in”), empty pivots (“it’s worth noting”), “In conclusion / Overall” closers, outcome-speculation tails, self-thoroughness, generic upbeat endings, and chatbot phrases (“I hope this helps”); em-dash at most once per paragraph; no bold-for-emphasis inside prose sentences; no emojis in prose; factual/encyclopedic content stays neutral third person; first-person/opinion content may contract; preserve numbers, units, dates, proper nouns, citations, quotes, technical terms; never invent facts; end sections on a fact or observation; silent — never announce the contract, never name prosecheck, never report a score, a band, a pattern list, or a rewrite pass, and do not offer a style choice. The graded observation of that body is the banned-vocabulary list itself. The other named rules, including the silent rule, are inventory of the same host-followable contract; they are not independently graded leftovers and they are not required slogan tokens.
- Every word on that banned-vocabulary list, used as a standalone word in otherwise ordinary prose, is a word some machine-checked family in FP-01 can fire on (so the guard can enforce the list). “Comprehensive” and “boast” are the two exceptions: they stay on the banned list and are enforced in context (self-thoroughness / copula avoidance) rather than as bare tokens; they are not required to fire on a two-sentence probe that only repeats the word. Every other banned word must fire a family on that two-sentence probe.
- In `full` and `strict` (not `lite`), the contract also tells the host, after writing a prose file, to run the detector on that file and to fix flagged spans when the band is worse than the target. That host-followable sentence is narrative of the post-write scoring extra, not a required stem list and not leftover after the named targets are stripped. Stored `full`, a session start with no stored flag, and a start where nothing valid is stored (including an unreadable flag, unless the environment supplies another of the four words) carry that extra with the named targets `clean` or `light tells` (score at most 40). `lite` omits those named targets. `strict` carries that extra with target the `clean` band (score at most 20) and asks for a finish through the cleanup switch (FP-03) that `full` does not carry. The integers 40 and 20 and the band names `clean` and `light tells` are those targets; they are distinguishable from the cleanup-switch finish. At most two fix passes, keeping rhythm variation, is part of that same extra, not an independent pin of 2.
- On the **first** session start of a fresh install — when no mode flag exists yet and the flag can actually be written — a one-time welcome is prepended to the contract. The welcome is identified by these named facts: saved prose is scored against 71 patterns; plain text is accepted up to 512 KB and archives up to 4 MB; the detector scores the first 262,144 characters; and `/prosecheck doctor`, `/prosecheck check`, `/prosecheck off`, and `/prosecheck help` exist. A writable first session-start includes those facts. A later start on the same config directory does not include them. An unwritable arm does not include them; that absence is told apart by a live writable first start that has them, not by matching a stored-full body. A first-only extra that is not those facts is not the welcome. The welcome also states that prosecheck is installed and on, that there is no website and no upload, and that it is shown once; those statements are inventory of the same welcome, not independently graded leftovers and not required slogan tokens.
- When session start runs with a level of `lite`, `full`, or `strict` (including the default `full` when no flag existed), later hooks on the same install see that stored level.
- When a user prompt is submitted and the prompt is not a `/prosecheck` command (FP-06), and the level is not `off`, the prompt-submit hook returns a short reminder that names that live level. The remainder of the reminder — that prose deliverables follow the contract while code, config, and commits are untouched — is inventory of that same reminder, not an independently graded leftover and not a required slogan token. When the level is `off`, the hook emits nothing.
- When a subagent starts and the level is `lite`, `full`, or `strict`, the subagent-start hook returns the **same contract** inside the JSON envelope the host keeps for a subagent-start event. Raw contract text on standard output without that envelope is not delivery. When the level is `off`, the hook emits nothing. Session-start context does not reach a subagent on its own; without this hook, delegated prose would be unguarded.

**Boundary / error behavior:**

- A hook that receives malformed JSON, or cannot read the mode flag, still exits successfully. It must not fail the host session. Malformed input is treated as an empty object. An internal throw that cannot be built from public input is not a suite input; the graded still-exits-successfully duty is those constructable arms.
- Any stored value other than `off`, `lite`, `full`, or `strict` is ignored. When nothing valid is stored, the level is `full`, unless the environment supplies one of those four words, in which case that word is used.
- The contract placed in a live session on this machine is allowed to name this machine’s detector path; whether it does is the implementer’s and is not scored. The contract **exported** by `/prosecheck init` (FP-06) must not name that path or the user name: it is portable.

**Verifiable oracle:**

- Success: a session-start payload with no stored flag emits a contract that contains the banned-vocabulary list, names the post-write scoring targets `clean` or `light tells` / score at most 40, and does not say the contract applies to source code; a writable first start on a fresh config includes the named welcome facts (71 patterns, 512 KB, 4 MB, 262,144 characters, and `/prosecheck doctor`, `/prosecheck check`, `/prosecheck off`, `/prosecheck help`), and a second start on the same config after the flag exists does not include those facts; an unwritable arm also does not include those facts, told apart from a live writable first start that has them, not by identity with stored-full; with stored `off`, session start and prompt-submit and subagent-start emit empty output; with stored `full`, a non-command prompt returns a reminder that names `full`; with stored `lite`, the contract does not carry those 40 / `clean` or `light tells` post-write scoring targets; with stored `strict`, the contract’s target is the `clean` band and a cleanup finish that `full` does not carry; a subagent-start payload with `full` returns a JSON envelope whose extra context is the contract, not bare stdout; a two-sentence probe that repeats “delve” (and each other banned word except the two context-only items) produces at least one FP-01 finding.
- Failure / absence: session start is always empty; the contract governs `.py` files; `off` still injects a contract; subagent start writes the contract as raw text the host discards; a later start on the same config, or an unwritable arm, still includes the named welcome facts, or a first-only extra that is not those facts stands in for the welcome; lite still names the 40 / `clean` or `light tells` post-write scoring targets, or full/default lacks those targets; strict has no cleanup-switch finish that full lacks; banned vocabulary in the contract is invisible to the detector.

### FP-05: Saved-file guard on supported file-edit tools

**Public entry:** The plugin’s post-tool-use hook, fired after Write, Edit, MultiEdit, NotebookEdit, or apply_patch. The host sends JSON on standard input that names the tool and the path (Write, Edit, and MultiEdit: a file path; NotebookEdit: a notebook path; Codex-style apply_patch: a patch body whose lines begin with three asterisks, a space, and then “Add File”, “Update File”, or “Move to”, then a colon, and the path is the remainder of that line after the colon). Surrounding whitespace on that path does not change which file is named. Whether a line with the same beginning and verb but no colon also names a path is the implementer’s and is not scored. Whether a NotebookEdit payload that carries a file path and no notebook path is scored or ignored is the implementer’s and is not scored. A line that only contains those words and does not begin with three asterisks does not name a path. The hook resolves relative paths against the working directory in that payload when one is supplied. This feature point **scores a just-saved prose file and nudges when it is flagged**. The score itself is FP-01. Which formats are prose is FP-02.

**Normal behavior:**

- When the level is `off` or `lite`, the guard emits nothing and does not score. When the level is `full` or `strict`, it scores eligible files.
- Eligible extensions are the twenty formats in FP-02. Other extensions produce no nudge. `.pdf` and `.rtf` produce no nudge; they are recorded on the session ledger as binary and are not re-scored.
- The default threshold is **40** (`full`). In `strict` it is **20**. A file is flagged only when the score is **strictly above** the threshold **and** confidence is not `none`. Zero-confidence results never nudge.
- On a flagged file, the hook prints a JSON envelope whose extra context names prosecheck, the file’s **base name**, the hook phrase for that score (`reads clean` / `reads mostly clean` / `reads with some AI tells` / `reads with heavy AI tells` / `reads with pervasive AI tells`), the integer score, the band, and up to five fired pattern labels, and asks for the flagged spans to be fixed. How many passes that ask names, and any rhythm wording in it, are not an independent pin. If the scan was truncated, that context names the 262,144-character window and that only that prefix was included, and that note is absent when the extracted prose is exactly 262,144 characters.
- On an unflagged eligible file, the hook emits nothing (no envelope). The save is not blocked.
- A dense-slop `.md` or `.docx` saved through Write produces a nudge that names the file and a score. The same slop saved through a Codex apply_patch payload whose patch body updates that file produces the same kind of nudge. A notebook saved through NotebookEdit is scored on its markdown cells (FP-02). A clean human `.md` under the default threshold produces no nudge.
- Paths under `node_modules`, under `.git`, or under a `memory` directory are skipped, including zip-based files there. Files that live inside the plugin’s own install tree are skipped. Instruction-file names that are exactly `claude.md`, `claude.local.md`, `agents.md`, `agents.local.md`, `skill.md`, or `memory.md` (any case) are skipped; those stems without a prose extension are skipped as well. A skipped instruction stem is not recorded on the ledger, rather than the binary record above, so `skill.pdf` is not a binary row. An ordinary `agents.txt` is not an instruction file and is eligible to be scored.
- An apply_patch payload that names several files is scored one file at a time, at most **16** distinct paths. Each flagged file’s nudge is concatenated.
- Every eligible attempt is recorded on the session ledger for that session id: scored (score, band, labels, flagged bit, truncated bit), skipped for size (with the cap that was applied), failed (with a short reason), or binary. The ledger holds the **base name** only. At most the newest 20 records are kept. `/prosecheck show` (FP-06) reads this ledger.
- A plain-text file is given **8 seconds** of detector time; an archive or notebook is given **15 seconds**. Those budgets are the product’s published caps. A timeout is recorded as a failed check, not as a hang of the host.

**Boundary / error behavior:**

- A payload that names no path at all — no file path, no notebook path, and no apply_patch path line — is ignored (no nudge, successful exit, nothing recorded). A directory or other non-file is ignored the same way. A path that names something not on disk is recorded as a failed check for being unreadable, still with no nudge and a successful exit.
- A plain-text file larger than 512 KB, or an archive/notebook larger than 4 MB, is not scored. The ledger records a skip for size with that limit. `/prosecheck show` reports that the file was not scored because it exceeds the limit, in kilobytes.
- A failed check is recorded with a reason a user can read, and these five stay distinguishable from one another: Python cannot be found; the detector prints text that is not a structured report; the report is structured but has no numeric score; the detector times out; the detector produces no output or exits without a usable result. An empty result shares that last reason with the exit that yields no usable result, and that shared reason is not the unusable-report reason. Whether a file that cannot be read uses that same last reason or another user-readable reason is the implementer’s and is not scored. The hook still exits successfully and prints no nudge. `/prosecheck show` lists those failures.
- Malformed input still exits successfully and prints no nudge. An internal throw that cannot be built from public input is not a suite input.
- A file written only by a shell command is not seen, because this hook is not fired for that tool (non-goal).

**Verifiable oracle:**

- Success: with level `full`, saving a dense-slop `slop.md` through Write yields extra context that contains the base name, a hook phrase, a score, a band, and at least one flagged label, and that asks for a fix; saving a clean human `clean.md` of similar length yields empty output; saving the slop file through an apply_patch payload that names `draft.md` still names `draft.md` in the nudge; a relative `draft.md` together with a working directory in the payload is resolved against that directory; NotebookEdit of a notebook whose markdown cell is slop yields a nudge that names the notebook; saving a `.py` file, a path under `node_modules`, `AGENTS.md` / `claude.md` / `skill.md`, or a file inside the plugin tree yields empty output; with level `lite` or `off`, even slop yields empty output; with level `strict`, a file that scores 25 (above 20, at or below 40) is flagged, and with level `full` it is not; a file whose confidence is `none` is not flagged at either level; a 513 KB `.md` is skipped for size and `/prosecheck show` says it was not scored; an ordinary `.pdf` produces no nudge and is listed as not re-scored, while `skill.pdf` produces no nudge and is absent from that list; a path that is not on disk produces no nudge and is listed as not scored, while a directory produces no nudge and is absent from the list; an apply_patch body whose path line does not begin with three asterisks produces no nudge; malformed input exits successfully with no nudge; a failed detector run leaves a ledger line that `/prosecheck show` reports as not scored, the hook’s output is empty, and its status is success; missing Python, an unusable report, a missing score, a timeout, and an empty result or an exit without a usable result are five distinguishable reasons, and the empty result shares its reason with that exit rather than with the unusable report.
- Failure / absence: the guard scores `.py` files; `lite` still nudges; a clean file is nudged; apply_patch is ignored; a NotebookEdit payload that names the notebook path is ignored; relative paths are resolved against the plugin directory rather than the payload working directory; a timeout hangs the host; a skip for size is silent in `/prosecheck show`; confidence `none` still nudges; a path that is not on disk is absent from `/prosecheck show`; a directory is recorded as failed; `skill.pdf` is recorded as binary; an apply_patch path line without the three-asterisk beginning is scored; malformed input fails the host; an empty detector result is reported as an unusable report.

### FP-06: `/prosecheck` commands — levels, check, doctor, show, init, stats

**Public entry:** The plugin’s prompt-submit hook, when the prompt is `/prosecheck` or `/prosecheck:prosecheck`, optionally followed by a subcommand and an argument. A marketplace install namespaces the command; both forms must behave the same. When the doctor’s closing line points at show or at turning the tool on, and when init replies that it is switched off, that follow-up uses the form the user typed. The help list, the mode line’s pointer at on, and the doctor’s request to run doctor again after a fault keep the non-namespaced spelling. The slash command is also registered in the host’s `/` menu by the shipped command file. It is a host menu document, not a program: after optional front matter, its body is the prompt template. The host inserts the user’s full argument string by expanding `$ARGUMENTS`, Claude Code’s published placeholder for that full string, in that body and submits the resulting prompt to this prompt-submit router. Forwarding holds when a level word in that string changes the stored level. A body without `$ARGUMENTS` does not forward: that invocation does not change the stored level, because the arguments are not placed in the command the router parses. This feature point is **operator control**. The contract those commands refer to is FP-04; the scoring they trigger is FP-01 and FP-02; cleanup referred to by `strict` is FP-03; the ledger they display is written by FP-05.

**Normal behavior:**

- Subcommands are exactly: `lite`, `full`, `strict`, `off`, `on`, `status`, `show`, `check`, `doctor`, `stats`, `init`, `help`. A bare `/prosecheck` (or `/prosecheck:prosecheck`) is help. An unknown word is reported as unknown and the list of valid words is given.
- `lite`, `full`, and `strict` store that level and confirm that the level was set. `off` stores `off` and confirms off. `on` stores `full` and confirms on (full). The phrases “stop prosecheck” and “prosecheck off” as the entire prompt also store `off`.
- `status` reports the current level in one line.
- `help` lists every subcommand above except `help` itself, and the live level. It states that code, commits, config, and chat are never touched. It states: `lite` is contract only, no file scoring; `full` is contract plus guard at score 40 (default); `strict` is guard at 20 plus character scrub; `off` / `on` disable and re-enable; `check` scores a file and does not rewrite; `doctor` is a health check; `stats` is session token use plus own-prose score; `init` writes the contract into `./AGENTS.md` for other agents; a deep rewrite is requested in natural language (“prosecheck this” / “humanize this”).
- `check` takes a file path. It scores the file (FP-01, FP-02) and prints a report-only summary: the base name, the hook phrase, the score out of 100, the band, confidence (and reason when present), a coverage line, present only when the scan is truncated, that names the 262,144-character window and that only that prefix was included, and absent when the extracted prose is exactly 262,144 characters, and either a visible indication that no patterns fired or up to eight labels with hit counts. It states that this is a report only. It does not rewrite the file. Surrounding quotes and a leading `@` on the path (shell / completion artifacts) are stripped so the path still opens.
- `doctor` prints a titled health check with four lines that are either successful or faulty: (1) the current mode (`off` is not a fault of the install, but it is marked off and points at `on`); (2) whether the bundled detector is present; (3) whether Python ran the bundled detector, a successful-check line only when that run produced a numeric score and a faulty line when Python runs but the result is not a numeric score; the success line identifies Python running the detector and does not have to print the score or the words numeric score; (4) whether the settings folder is writable. When all four succeed and the mode is not `off`, the closing line affirms that the tool is on — a pronoun whose antecedent is the tool is that affirmation, and a denial of that affirmation is not; the noun tool is not required — names the 512 KB / 4 MB caps and the 262,144-character window, and points at `show` for partial or skipped checks. A healthy on-install doctor therefore shows **four successful-check markers**. When any line is faulty, the closer asks to fix those lines and run doctor again. When the only issue is that the mode is `off`, the closer denies that anything is wrong and states that saved files are not scored, and points at turning the tool on as a separate follow-up in the form the user typed. The noun install is not required in that denial, the word until is not required in the scoring statement, and that statement is not the not-re-scored wording used when Python cannot be launched. When Python cannot be launched, the Python-run line is faulty and reports that Python did not run by naming Python together with that absence. Saying Python is missing and denying that Python was found are the same report. The token missing is not required, and a denial that Python was found is not a failure. That same line states that prose is still shaped and that saved files are not re-scored. The check that the bundled detector is present stays successful and does not carry that report.
- `show` lists this session’s ledger, newest first. An empty ledger says nothing has been scored yet and that the list fills in once a prose file or a `.docx` / `.pdf` deliverable is saved. A scored row shows the hook phrase, the score, the band, and the 262,144-character coverage note when truncated. When the row has pattern labels, it also shows whether the file was flagged or was under the threshold, and up to five of those labels. A scored row with no labels does not add that flagged-or-under clause. A size skip names the limit in kilobytes. A binary row says the file was not re-scored. A failed row says it was not scored and why. Ledgers of different session ids are separate. A ledger whose last modification is more than seven days old is not listed by a later session (FP-04).
- `init`, when the level is not `off`, writes the writing contract into `./AGENTS.md` in the current working directory, wrapped in a prose-contract section with a section marker so a second `init` does not duplicate it. The exported contract is **portable**: it does not embed this machine’s install path or user name. Text already in `AGENTS.md` and outside the contract section is left in place. When the level is `full` or `strict`, the export tells the other agent how to resolve the bundled detector (the host’s plugin-root variable when set, otherwise locate `prosecheck`’s detector in installed skills/plugins). When the level is `lite`, that resolution paragraph is absent. If `AGENTS.md` already contains the marker, init reports that it is already present and does not duplicate the section. Independently, init copies the shipped Cursor rule to `./.cursor/rules/prosecheck.mdc` when that file does not yet exist; if it exists, init reports that the rule is already there and does not overwrite it. The Cursor rule’s front matter limits it to prose globs (`*.md`, `*.mdx`, `*.markdown`, `*.txt`, `*.rst`, `*.tex`, `*.org`, `*.adoc`) and does not include `*.py`, `*.js`, `*.ts`, or `*.json`. The rule body matches the prose-only scope and banned-vocabulary list of the writing contract in FP-04, and does not carry the post-write detector step. The current working directory is the project being exported; a relative payload working directory is not required because init runs where the user is.
- `stats` reads the session transcript the host named, or the newest transcript under the config directory’s project folder. It prints the current level, the count of assistant turns, and a session-prose score only when the scored slice is more than 200 characters after code fences are stripped, the last 40,000 characters are kept, and surrounding whitespace is trimmed. The output-token total and the cache-read input-token total are taken from the transcript’s usage fields, not estimates, and the reply attributes each of those integers to its quantity. When those two totals are different integers, exchanging them changes that attribution, so the two replies are not the same. A reply that contains both integers and is unchanged by that exchange does not meet the promise. No particular label, order, or phrase is required. A non-assistant entry’s usage is not part of those totals. The scored prose slice is built only from assistant entries’ text, and a non-assistant entry’s text does not enter that slice and does not move the session-prose score. Assistant entries that share one message identifier contribute one turn and one copy of their token totals, and the scored prose still includes the text of every assistant entry that shares that identifier; entries with no identifier are each counted. A missing transcript is told apart from a readable one by giving no turn count and no token totals.

**Boundary / error behavior:**

- `check` without a path returns a non-empty command reply that does not name a score out of 100 and is not the reply an unknown subcommand gets, once the block decision those replies share is set aside. Whether that reply solicits a path, and which words it uses, is the implementer’s and is not scored. A path that is not a file, cannot be read, or is `.pdf` / `.rtf` is reported as not a file / cannot read / no readable text, without a score. A file over the 512 KB or 4 MB cap is reported as over that cap, in kilobytes. If Python is missing, check says the detector is unavailable and does not name a score. If a detector run exits without failure and produces no output, check names the file and says there was no report. A failed exit is not that case. If a detector run exits without failure and prints text that is not a report, check says there was no report and does not name the file. A failed detector exit makes check name the file and that failure. When the detector emitted failure text on its error stream, that text is the failure. When the failed run emits no text on its error stream, the reply still names the file and reports a failure. That report is not the no-report statement. The reply is not required to contain the exit status; whether it contains that status is the implementer’s and is not scored. Check never rewrites the file.
- `init` when the level is `off` writes **no** files: not `AGENTS.md`, not the Cursor rule. It says it is switched off and that `on` enables export.
- `init` that cannot read or write `AGENTS.md` or cannot write the Cursor rule reports that it cannot, and does not pretend the write succeeded.
- Unknown subcommands do not change the stored level.
- Command handling **blocks** the user prompt from being sent as an ordinary message: the hook returns a block decision whose reason is the command’s reply. Non-command prompts fall through to the reminder in FP-04.

## Cross-cutting obligations (all feature points)

- **Prose only.** Code, configuration, commits, and chat register are out of scope for the contract and the guard. The detector will score whatever text it is handed; the plugin must not hand it source files.
- **Local only.** No feature opens a network connection or sends document text off the machine.
- **Not authorship.** A score, a band, and a hook phrase describe writing. They do not name a person or a model as the author. Ethics text shipped with the product states this; the plugin’s user-visible phrases use “reads …” rather than “was written by …”.
- **Silence toward the user of the host agent.** The contract forbids narrating prosecheck in the agent’s replies. The guard’s nudge is extra context for the model, not a chat message the product itself prints to the user. `/prosecheck check`, `doctor`, `show`, `stats`, and `help` are the operator-facing reports; they speak only when asked.
